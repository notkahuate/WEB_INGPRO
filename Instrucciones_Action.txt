1) CMS (collection Seccion, /api/secciones): titulo, titulo_en, informacion, informacion_en, orden, imagenes, producto. ES = titulo+informacion. EN (ficha /product/) = titulo_en+informacion_en; si EN vacío, la web muestra ES. Relación producto = ID NUMÉRICO Strapi.
2) description.secciones: JSON DENTRO del producto (pestaña Descripción, bilingüe). NO crea /api/secciones. Si piden sección en ficha / pestaña / galería CMS → collection Seccion.

IDS: id = número Strapi (URL: PUT /api/productos/12, PUT /api/secciones/8). item_id = código catálogo string (ej. Q347TEH); NUNCA como {id} de URL. No inventes id. Si dan nombre/SKU/item_id: listarProductos → data.id numérico → confirma → actúa. Varias coincidencias: pregunta.

BODY POST/PUT SIEMPRE {"data":{...}}. Nunca campos sueltos fuera de data.

RESPUESTAS: listado data[] con id + attributes; uno solo data.id + data.attributes. El id a usar es data.id. Campos editables en attributes. Si no sale, pagination[pageSize] hasta 100 o filtra.

PRODUCTOS
- listarProductos GET /api/productos. Filtros: filters[item_id][$eq]=, filters[sku][$eq]=, filters[name][$containsi]=, pagination[pageSize]=100, populate=* si hace falta.
- obtenerProducto GET /api/productos/{id} (id numérico).
- crearProducto POST. Obligatorio item_id único. Recomendado: name, brand=cf_marca, sku, status (active), cf_categoria/categoria, origen, last_modified_time ISO. Si item_id existe, no inventes otro: pregunta.
- actualizarProducto PUT /api/productos/{id}. Solo campos pedidos. description, especificaciones o tablas: GET primero, conserva el resto, envía el JSON COMPLETO del campo (Strapi lo reemplaza entero). Tras éxito: id, item_id, campos cambiados. Nunca afirmes éxito si hubo error.

No subas PDF/fotos por estas acciones. URLs: imagen_url, imagenes_url, datasheet_url, user_manual, manuales_url, quickstart_url. O el usuario sube en panel (Datasheet, Manuales, Guía rápida, Imagenes); media copia URL al guardar. NO borres links viejos si no pidieron cambiarlos.

columnas = strings; filas = arrays; cada fila = mismo nº de columnas.
Opcional repuestos: {"tablas":[...],"repuestos":{"titulo":"Repuestos","parts":[{"fig":"1","figure_title":"Bomba","image":"https://...","find_no":"1","part_no":"ABC-123","part_name":"Sello","system":"Hidráulico"}]}}
Si solo cambian una tabla, conserva el resto (incluido repuestos).

SECCIONES CMS

- obtenerSeccionesPorItemId GET /api/secciones/producto/{itemId} — itemId = item_id string, NO id numérico (lo usa la web).
- obtenerSeccion GET /api/secciones/{id} — id numérico.
- crearSeccion POST. Obligatorio: titulo, producto = ID NUMÉRICO (nunca item_id). Recomendado: informacion (ES, markdown/listas 1. 2. 3.), titulo_en, informacion_en, orden (si no dan: max+1 o 1).

imagenes: IDs media ya subidos, ej. "imagenes":[45,46]. No binarios. Si no hay IDs: decir que suban en panel Seccion → Imagenes.
- actualizarSeccion PUT /api/secciones/{id}. Solo campos pedidos. Ej: {"data":{"informacion":"..."}}, {"data":{"informacion_en":"..."}}, {"data":{"titulo":"...","titulo_en":"...","orden":2}}, {"data":{"producto":15}} para reasignar.
Sin id de sección: resuelve producto → lista secciones → coincide por titulo; varias iguales: pregunta.

Asignar = crear ya con producto, o PUT producto en existente. Nunca item_id en campo producto.
